# 声音选择与试听

## 选材顺序

先明确整段内容的节奏和情绪，再选择能形成连续配乐的素材。音乐不必固定一种类型；判断它是否留得出阅读和理解空间，以及重要段落能否自然衔接。

音效从具体内容事件出发：对象出现、机制启动、关系改变、动作完成、结论强调。开始和结束可以有不同声音，不绑定固定素材或升降调公式。它们应在当前上下文中容易辨认，又不破坏整体质感。

素材优先考虑用户指定素材和本项目可用素材；按需要读取素材索引。素材不足时可以先制作画面，做无配乐预览或制作少量简单程序音效。简单正弦提示音和鼓点不是完整 AI 配乐；未接入的生成服务不作为已具备的能力。

## 新版音频配置需要表达的内容

| 字段 | 如何填写 |
| --- | --- |
| role | music/start/end/transition/process/accent，描述用途而不是音色 |
| purpose | 此声音帮助解释哪个内容变化；启用音效时必填 |
| musicFit | 当前候选与配乐的搭配判断或明确的待试听问题，不伪造已确认结论 |
| source、sourceIn、sourceOut | 本项目内素材和原素材秒数 |
| at | 成片秒数或命名事件引用 |
| gain、buses | 单项及角色的相对音量；不能只凭峰值判断可听见 |
| enabled | process 需显式 true；不需要的声音可以关闭，而无需删除候选 |
| ducking | 必要时在事件附近降低 music 音量并恢复，不改节奏和位置 |

详细字段与合法范围读工程自身的音频工作流文档。新建骨架的默认方案为空；example 中的候选未启用。把路径填对不代表音效已经选好。

配乐避让的 at 是达到目标音量的时刻，attack 向前展开，hold/release 向后展开。重叠避让取最强一次；不为每个小动作都安排明显的音乐起伏。

## 过程音的判断

普通位置移动不必有过程音。持续加速、倒计时、压力积累等变化可能受益于声音，但仍需与配乐一同听。

过程声可以连续也可以分段；选择依据是表达，不是“连续一定更好”。持续有音高的声部可能形成另一条旋律，细碎音点可能像额外节拍，宽频噪声可能有摩擦感。出现冲突时先检查是否需要该层，再调整音色、频段、密度、时长和音量。

对“要连贯”的反馈，判断用户是在说音乐衔接、动作声音还是整体节奏。可以用统一声学质感、自然收尾和合理留白建立连贯感，不自动增加一条持续声部。

## 处理常见听感反馈

| 反馈 | 先检查什么 | 可选调整 |
| --- | --- | --- |
| 结束音听不见 | 事件是否正确、混音中是否存在、是否被配乐掩盖、衰减是否过快 | 调整音色和有效时长、适量增益，必要时配乐短暂避让 |
| 过程声吵或混乱 | 是否形成额外旋律/节拍，持续声是否真的解释内容 | 减少或关闭该层，选更合适素材，再考虑音量 |
| 转场不舒服 | 与画面交接是否同步、尾音是否拖到下一动作 | 改触发位置、素材或收尾，不只加新效果 |
| 开始与结束不像一套 | 声学质感、空间感和响度是否协调，能否听出功能 | 保留用户认可部分，选择适配的变体；允许不同素材 |

用户已认可的部分在迭代中保持可追踪。需要比较时，优先一次改变一个影响听感的维度，避免同时改画面、配乐速度和全部音色导致无法判断原因。

## 试听与证据

先按实际音量听完整混音，必要时切到配乐或音效定位冲突，再回到混音判断。A/B 保持相同片段和播放音量；候选方案先写另一份音频 JSON，不直接覆盖现用配置。

当前工具的峰值、RMS、采样和浏览器检查只能验证技术结果。若当前执行环境不能真正听到音频，应核对技术证据并交付可播放片段，请用户给听感反馈；不要声称亲自试听过。此前的源码波形检查也不能证明某个音色好听。

试听页的 listened 表示检查项被勾选，不代表接受方案。实际问题和选择写进备注，下载记录后按需归档到本期。没有必要为了得到一个勾选而阻止其他已授权的内容、画面和导出工作。

对外发布所需素材许可依据用户素材来源和实际用途确认；本地生成示例不等于素材可再分发。不要自动发布或把原音乐打包进 Skill。
