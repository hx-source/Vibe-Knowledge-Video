# 工程结构与边界

本文描述目标架构。除配置骨架和结构检查以外，模块功能均待实现。

## 数据流

```text
资料与事实 → 分镜 / 字幕 / 内容事件 → 时间轴编译 → Remotion 场景
                                   ↓
                           音频计划 → 混音与分轨
                                              ↓
                统一素材准备 → 预览 / 局部审片 / 视频导出
                                              ↓
                                  检查报告与来源清单
```

## 模块分工

| 目录 | 职责 | 边界 |
| --- | --- | --- |
| src/compositions | 注册整片和片段，读取已解析的项目数据 | 不重新计算音频计划 |
| src/components | 文字、箭头、节点、连接线、字幕等图元 | 不内置具体知识结论 |
| src/scenes | 时序图、对比、状态变化等讲解形式 | 与配色主题分离；按真实需求逐步增加 |
| src/timeline | 事件解析、秒与帧、片段局部时间 | 所有消费方共用一套规则 |
| src/themes | 配色、字体、布局和运动参数 | 不决定知识内容和讲解时长 |
| src/audio | 将混音结果挂到视频时间轴 | 不维护第二份增益、音效或避让计算 |
| src/review | 同画面 A/B、分轨、范围循环 | 人工结论与数值报告分开 |
| scripts | 文件读取、配置校验、素材准备、混音、渲染 | 文件系统和 FFmpeg 逻辑留在本机侧 |
| templates/starter | 新一期的最小文件集 | 不把旧音效实验当成默认方案 |
| projects | 每期事实、配置、字幕、专属场景和素材 | 专属场景验证后再考虑提炼为公共能力 |
| assets | 公共原始素材及来源信息 | 不混入生成的最终混音 |
| public | 浏览器可访问的准备后素材 | 项目引用素材标识，不硬编码磁盘路径 |
| outputs | 项目、修订、区间对应的输出 | 原始素材与配置不写回这里 |

## 设计约束

1. 配置采用成片秒数，编译后得到整数帧；按绝对边界转换，区间左闭右开，避免独立舍入片段时长造成累计误差。具体舍入策略在时间轴实现阶段固定并验证。
2. 场景动画只由输入数据、帧号和固定种子决定，不依赖播放历史或墙上时钟。任意跳帧和逐帧导出必须一致。
3. 片段使用局部时间。改画面而不改时长不移动后续片段；改时长须重新计算后续位置，并复查衔接及配乐。
4. 混音使用全片时间。局部预览与导出裁剪同一份混音，不能从片段起点重启背景音乐或丢失跨边界声音尾部。
5. 素材准备只复制被引用的文件到 `public/prepared/<project>/<revision>/`，并生成可追溯映射；不将整个工作目录公开。
6. 字体和媒体完成加载后再渲染。字体缺失、素材缺失不能静默生成正式成片。
7. 新项目默认 1920×1080、30 fps、无配音、空音频；静音须显式标注。横竖屏和其他分辨率需要布局验证。
8. 初期保留现有音频编排算法，但正式接入应迁移实现与检查，不能长期跨目录导入旧工程内部文件。

## 旧工程处理

旧工程 v0.3 只作参考与对照，不更改其入口。旧版全局 1.25 倍速不是新工程默认值。迁移旧主题时显式转换字幕、事件和声音的时间含义，不能仅改版本号。

## 安装阶段再确定

React、Remotion、TypeScript 及必要的渲染/播放依赖在运行入口阶段选择兼容版本并固定锁文件；相关 Remotion 包版本保持一致。先实现本地运行，不引入云服务或额外音乐生成服务。
